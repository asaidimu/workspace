# Phase 3: registry, pipeline and providers

## Context

Spec: `todo/specs/Workspace specification.md` §13 (registries/providers/extension
points), §16 (testing: golden prompts, recorded HTTP, replay provider),
§17 Phase 3 gate: **"golden prompts match, recorded-HTTP tests pass for
every adapter, and streaming and cancel tests pass on the replay
provider."** Decision D10 (§17): first adapters are **Anthropic, OpenAI and
Gemini**, plus a replay provider for tests.

State so far: Phase 0 fixtures committed (`testdata/ts-fixtures/{prompt,
registry,turntree}.json` — generated by `fixtures/gen-*.ts` against
`@asaidimu/utils-workspace@9.0.0`); Phases 1–2 green (`todo/done/anansistore.md`
all `[*]`, full gate `-race -count=3 -shuffle=on` passes). **No test has
ever read the ts-fixtures** (verified by grep) — all three goldens are
unconsumed. `provider/provider.go` defines the complete port (Provider,
Request/Response/Stream/Event, Capabilities, Pricing, CredentialSource) but
**no adapters, no SSE decoder, no ReplayProvider** exist; `workspacetest`
has only `ScriptedProvider` (in-process fixed events, no HTTP, no
cancellation semantics beyond ctx). `content.Registry` + JSON-schema
reflection exist with unit tests; `prompt.Pipeline` exists with behavior
tests (determinism, ordering, fitting, compaction) but no golden comparison.

Fixture formats (verified):
- `prompt.json`: `{fixture, ts, cases[]}`, cases = `{name, input{provider,
  prompt, extensions}, expected{sectionLabels[], system, transcript[],
  schema, logs[]}}`; 4 cases: minimal, full-sections, extension-anchors,
  transcript-mapping.
- `registry.json`: 8 cases (default-types-modes, tool-call-regex-fallback,
  parse-unknown-and-unmapped, parse-provider-mapping,
  schema-emittable-exclude-tool-call, instance-filter-flags,
  process-tool-call-commands, format-renderers).
- `turntree.json`: turn-tree cases (Phase 1's kernel passed without
  consuming them — fold consumption in here or as a kernel golden test).

Dependency rules: adapters use plain `net/http` + one shared SSE decoder
(no vendor SDKs, no new module deps — **never `go get`/`go mod tidy`**);
no hestia imports in core; anansi persistence stays inside
`store/anansistore`.

## Key spec facts

- Provider port (already written): `Name/Models/Capabilities/Generate/
  Stream/UploadFile`; streaming = `Stream` of typed `Event`s; usage in
  micro-KES (`Pricing.InputMicrosPerMTok`); `CredentialSource` yields keys,
  never stored/logged.
- §13: extensions register tools, block types, providers, prompt sections;
  switching providers (S8) drops thinking blocks and re-uploads missing/expired
  remote file IDs at assembly stage 6.
- §16: recorded HTTP tests per adapter; `ReplayProvider` serves recorded
  transcripts from `testdata/replays/` (recorded by `cmd/record` once
  against real APIs, stripped of secrets); fuzz the SSE decoder; cancel a
  streaming turn must close the provider request and cancel the run within
  1 s (§3 target table).
- §5/§15: block/tool parsing = `type string` + payload; tool schema route
  (decision 8): reflection from input type, validated — `content/schema_for`
  already implements this.
- Tokens: estimator bytes/4 default, custom tokenizer honoured (already
  tested in prompt).
